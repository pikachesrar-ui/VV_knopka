# Auto-QA v1

## Режим

Auto-QA работает локально через FFmpeg/ffprobe в режиме `critical`.
Перед автоматической загрузкой создаётся `*.qa.json`. Предупреждения и честные
`SKIP` не блокируют публикацию, но critical FAIL возвращает exit code 76 и
scheduler отказывается загружать ролик.

Стоимость OpenAI API: `$0`.

## Автоматические проверки

- наличие video/audio stream;
- точное разрешение 1080x1920;
- жёсткий диапазон длительности 10–60 секунд;
- рекомендуемая длительность 25–35 секунд;
- вероятные постоянные чёрные поля через cropdetect;
- чёрный или title-card-подобный старт;
- длинный чёрный хвост;
- integrated loudness и true peak;
- локальная политика music volume/voice ducking;
- нижняя safe zone для наших субтитров;
- порядок и границы SRT, когда отдельный SRT доступен;
- CTA в конце сценария;
- темп смены визуала из конфигурации/монтажного manifest;
- TikTok/Douyin-маркеры в source metadata.

## Честные ограничения v1

Смешанный финальный audio track не позволяет точно разделить голос и музыку.
Burned-in субтитры нельзя надёжно синхронизировать без анализа речи и кадров.
Правая safe zone и watermark внутри пикселей требуют CV/OCR. Эти проверки
получают `SKIP`, а не ложный PASS.

## Команды

Проверить один самый новый неопубликованный ролик:

```powershell
.\.venv\Scripts\vv-youtube.exe qa-ready --newest --limit 1
```

Проверить также уже опубликованные sidecars:

```powershell
.\.venv\Scripts\vv-youtube.exe qa-ready --include-uploaded
```

Отчёт создаётся рядом с MP4 как `slot-XX-....qa.json`.

Опция `--enforce` возвращает exit code 76 при critical FAIL. Штатный scheduler
использует её и для backlog, и для нового ролика. Неблокирующие warnings
остаются видимыми в журнале для дальнейшей калибровки.
