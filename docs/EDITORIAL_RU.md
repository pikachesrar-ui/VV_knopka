# Подача новых Shorts — direct_v1

Изменение от 2026-09-06. Пользователь разрешил реализацию после анализа CSV,
истории API, скриншотов Studio и двух MP4. Общий OpenAI бюджет остаётся $10.

## Основание

Снимок пользователя 2026-09-05 15:13 UTC: 20 public видео, pending=0,
66 просмотров проекта (39 AI / 27 cats). Studio показывает 69 просмотров канала,
включая 4 просмотра старых VTuber-видео; различие с API связано с несовпадающими
срезами (у slot 14 — 1 против 2). Лента Shorts — 10.1% от 69, около 7 просмотров,
не показов. У slot 5 средний просмотр 8 секунд из 20, 52.9% продолжили смотреть.
У slot 12 недостаточно данных об удержании. Это малая выборка; победитель формата
не установлен. До проекта был один подписчик — второй канал пользователя;
ссылками на новые видео пользователь не делился.

## Что меняется

`[editorial] enabled=true, start_slot=21` — только новые renders, не pilot 1–15.
Существующие MP4 не перегенерируются; CLI отказывается менять план/рендер слота,
для которого уже есть непустой MP4. Готовая очередь продолжает выгружаться прежде
новой генерации. Старые AI plans без editorial_profile сохраняют старый стиль.

### Котики

- Исходники проходят прежние provenance/audio/geometry/vision/reuse gates.
- Из прежнего набора 5–6 исходников выбираются 3–4 лучших reviewed moments
  с score >=6. Порог экспериментальный, не мера вероятности роста просмотров.
- Лучший момент идёт первым, второй по оценке — последним.
- Чёрные intro/transition/outro карточки и их повторяющееся мяуканье отсутствуют.
- Короткие подписи из существующего highlight-запроса показываются поверх кадра.
- Длина окна пока прежняя: 5 секунд. Автоматическое определение начала/конца
  действия по полноценному видео не реализовано; contact sheets не дают такой точности.
- Заголовок использует подпись первого выбранного момента; описание — описания
  выбранных кадров. Нет обещания заранее выдуманной общей темы для несвязанных клипов.
- `highlights.json` сохраняет полный обзор, `cat-edit.json` — выбранный порядок,
  исключения и пороги, `episode.json` — оформление/заголовок.
- При нехватке хороших моментов generation останавливается. Сохранённые оценки
  повторно используются; gate не запускает дополнительные платные попытки.
- История источников пока консервативно учитывает весь отобранный source pool,
  включая исключённые из монтажа клипы; source policy не ослаблена.

### Факты

- В существующий planner-запрос добавлены конкретный короткий hook, ответ сразу
  после него, один понятный механизм и запросы для доступных stock-сцен.
- Script обязан начинаться с точного hook (не больше 12 слов); проверка до fact-check/render.
- Все утверждения, включая hook, по инструкции входят в fact_check_items;
  прежний web-evidence gate сохраняется.
- Уже одобренные материалы ранжируются по совпадению metadata с первым поисковым
  запросом, затем идут в MPT sequential, без случайного перемешивания; clip duration 4 с.
- Это эвристика для начального кадра, НЕ покадровое соответствие озвучки видео.
  `match_materials_to_script=false` для curated stock остаётся честным ограничением.
- Planner ограничен 1800 output tokens. Provider usage учитывается до разбора
  JSON/проверки hook, чтобы не терять стоимость неудачного ответа.

### Бюджет и наблюдение

Новых платных стадий/провайдеров нет. Монтаж, фильтрация и заголовки котиков
используют уже полученные данные. Сохраняются оценки стоимости и local ledger
с лимитом $10. Это локальный guard на основе настроенных тарифов/оценок,
не отдельный банковский лимит OpenAI; текущий фактический остаток на ПК неизвестен.
Development/test run не делал платных вызовов.

`editorial_profile=direct_v1` записывается в upload sidecar и новые stats snapshots.
Старый sidecar без поля = legacy; отсутствующий/повреждённый sidecar = unknown.
Не сравнивать разные форматы лишь по средним просмотрам/час или лайкам при единичных просмотрах.

## Звук кошачьих роликов — 2026-09-12

Проверка присланного slot 22 выявила крупную разницу по пикам: кошачьи кадры
доходят почти до -1 dBTP, а мяуканье на старых карточках — до -8 dBTP.
Большинство сцен по интегральной громкости близки к -16 LUFS; одна тихая
сцена около -21.6 LUFS. Это старый ролик: он готов за 7 часов до коммита
direct_v1. Slot 21 также собран до коммита; оба не являются тестом нового формата.

Для будущих кошачьих роликов добавлены мягкий FFmpeg compressor перед
loudnorm и финальный limiter после громкости источника. Конфигурация
`[animal].source_audio_peak_db=-8` ориентируется на мягкость прежнего мяуканья;
цель интегральной громкости -16 LUFS. Слишком тихие исходники не вытягиваются
до уровня шумного фона. Новый direct_v1 убирает карточки и само мяуканье;
это измерение используется только как ориентир для комфортных пиков. На
образце будущий фильтр снизил peak второго источника с ~-1 до ~-7.6 dBTP.
После музыки и загрузки на YouTube нужен слуховой контроль, тесты не доказывают
одинаковую субъективную громкость разных источников.
