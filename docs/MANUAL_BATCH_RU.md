# Ручная серия из трёх Shorts

## Назначение

Ярлык `VV Knopka - 3 Shorts` позволяет в удобное время запустить три безопасных
цикла генерации и публикации. Первый готовый ролик публикуется сразу после
рендера, следующие — примерно через 60 минут после предыдущей публикации.
Рендер следующего выпуска может выполняться во время ожидания, поэтому лишнее
время по возможности не теряется.

Используются те же проверки, receipts, backlog-first порядок, QA и YouTube
channel binding, что и у ночного scheduler. Параллельный второй batch и
одновременный scheduler cycle блокируются. Дубли не создаются.

Серия считается по успешным публикациям. Если отдельная попытка остановилась на
fact-check, временной сетевой ошибке или другом штатном fail-closed gate, кнопка
автоматически повторяет тот же недостающий выпуск до трёх раз. Отклонённый
кандидат не засчитывается как один из трёх роликов. Проверки при этом не
ослабляются и не обходятся.

Если у AI-слота после одной замены доказанно исчерпаны источники/фактчек или
свежий полный аудит cats обоих настроенных стоков не смог набрать существующий
минимум источников, только этот слот получает статус `BLOCKED`: конвейер в этом
же цикле переходит к следующему. Не больше одного нового такого перехода за
запуск, чтобы ограничить расходы API. Временно недоступный внешний сервис,
старый аудит или отсутствие ключа провайдера не считаются основанием пропустить
слот. Запросы к стокам повторяются до трёх раз при transport error либо HTTP
429/500/502/503/504; сообщение об ошибке не печатает query/API key.

## Установка кнопки

После `git pull` и тестов выполнить один раз:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-manual-batch-shortcut.ps1
```

Будут созданы ярлыки на рабочем столе и в меню «Пуск». Windows не предоставляет
надёжной поддерживаемой команды для автоматического закрепления произвольного
ярлыка. Поэтому в меню «Пуск» нужно нажать правой кнопкой на
`VV Knopka - 3 Shorts` и выбрать **Закрепить на панели задач**.

После этого одного нажатия на значок достаточно. Откроется PowerShell с живым
журналом; окно нельзя закрывать до `SUCCESS` или `FAIL`. ПК не должен переходить
в сон, пока выполняется серия.

## Взаимодействие с ночным расписанием

Успешный ручной batch подавляет обычные триггеры 01:30/03:30/05:30 до 06:30
ближайшего утра. Поэтому нажатие вечером не создаст ещё три лишних ночных ролика.
Если кнопку не нажимать, ночной scheduler работает как раньше.

Пока batch выполняется, ночной запуск также пропускается. Если batch завершился
ошибкой, подавление снимается и ближайший ночной триггер сможет безопасно
продолжить с того же slot или backlog.

Состояние и журнал:

```text
runtime/scheduler/manual-batch-state.json
runtime/scheduler/manual-batch.log
runtime/scheduler/longrun-task.log
```

## Ограничения

- интервал считается между успешными публикациями; если рендер длится больше
  часа, следующий ролик выйдет позже, когда будет готов;
- YouTube upload limit, fact-check, source/provenance и остальные fail-closed
  проверки не обходятся;
- по умолчанию доступно не более трёх попыток на одну публикацию; после этого
  серия безопасно останавливается, чтобы постоянная ошибка не создала цикл и
  не расходовала API бесконтрольно;
- если сеть остаётся недоступной после ограниченных повторов, серия завершится
  с `FAIL`, сохранив неполученный слот для следующего запуска;
- серия считается по трём публикациям: существующий pending backlog при наличии
  будет опубликован первым и войдёт в эту тройку;
- расходы OpenAI зависят от типов следующих slots; ожидание и публикация сами по
  себе не расходуют OpenAI API. Повтор после отклонённого AI fact-check может
  вызвать ещё один ограниченный запрос планирования.
