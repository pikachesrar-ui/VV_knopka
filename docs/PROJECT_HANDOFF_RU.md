## YouTube source gates

Current intended production flow:

```text
official API CC search
-> one candidate/channel + thumbnail prescreen + reject memory
-> official CC recheck
-> LOW-RES preview
-> deterministic preview geometry/duration gate
-> contact-sheet-aware Luna temporal clean gate
-> only on PASS: production-quality download
-> full ffprobe near-9:16 + duration + audible audio
-> final full-quality clean gate
-> production sources.json only on PASS
```

Clean-footage v2 understands that the outer 2×2 contact sheet is generated by our pipeline. `source_frame_collage` only refers to a real collage inside an individual source frame; `multi_clip_sequence` requires strong evidence of unrelated clips stitched over time. Branding, social UI, large captions and real repost/compilation packaging remain fail-closed.

## Current fix: deterministic format preflight before Luna/full download

`src/vv_knopka/youtube_cc_preflight.py` now checks the low-res preview before any Luna call:

- real `ffprobe` dimensions;
- same `source_aspect_tolerance` used by production (`0.08` currently);
- minimum source duration (`animal.clip_seconds`).

A deterministic geometry/duration failure writes:

```text
runtime/slots/<slot>/youtube_preflight_rejects/<video-id>.json
```

with `durable_reject=true`. Future `cc-search` reject-memory includes these IDs. Transient decode/tool failures are recorded with `durable_reject=false` and remain retryable.

`youtube_cat_source_v6.py` was updated so its version-aware clean reject memory also unions these deterministic preflight rejects.
