## Current implementation: clean-footage v2 + CLI v6

New module:

```text
src/vv_knopka/youtube_clean_footage_v2.py
```

Entry point:

```text
vv-cat-youtube = vv_knopka.youtube_cat_source_v6:main
```

v6 keeps established v5 API/search/download logic and activates the v2 clean-review dependency only at CLI runtime.

v2 explicitly distinguishes:

- outer 2x2 = OUR analysis artifact, never source evidence by itself;
- `source_frame_collage=true` only if an individual tile itself visibly contains split-screen/collage/ranking layout;
- `multi_clip_sequence=true` only with strong evidence that unrelated source clips are sequentially stitched together (different cats/locations/camera sources etc.);
- ordinary movement/reframing/time progression is not enough.

Real branding, social UI, large captions and actual repost packaging remain fail-closed.

Prompt/review version was bumped so v1 cached decisions are not silently reused.

Reject memory is version-aware:

- old obvious branding/UI/caption rejects remain durable;
- stale v1 collage/compilation-only rejects are allowed one recheck with v2.

This means Pawcsu and `nWieRK7Fw-g` should remain remembered, while `hxXfevBB9Zs` can be re-evaluated.
